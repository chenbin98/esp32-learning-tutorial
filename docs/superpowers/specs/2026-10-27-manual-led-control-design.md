# 实战项目 01：网页手动控制 LED 设计

## 目标

在现有温湿度自动报警网页增加自动/手动模式切换。手动模式下，学习者可在网页点亮或关闭 D23 LED；自动模式保留现有 DHT11 双阈值报警行为。

## 设计选择

- 方案 A（选用）：明确的自动/手动模式。手动模式下网页 ON/OFF 指令控制 LED，温湿度采样继续更新显示但不覆盖手动状态；切回自动模式时按最新有效读数立即计算报警状态。
- 方案 B：手动命令只覆盖到下一次 DHT11 采样。实现较少，但 LED 可能在几秒后自行切换，网页操作结果不稳定。
- 方案 C：手动操作永久优先，直至再次手动操作。容易忘记自动报警已停用，因此界面状态容易产生误解。

## 行为与边界

- 启动后默认为自动模式，D23 初始为低电平。
- 网页提供“自动 / 手动”模式控件；手动模式显示“点亮 / 熄灭”操作，并明确当前模式和 LED 状态。
- 设备端 HTTP API 验证允许的 mode/on/off 命令；非法路径、方法或命令不改变 GPIO 状态。
- 沿用现有局域网 HTTP 服务，不增加身份认证；教程必须说明仅在可信本地 Wi-Fi 中使用控制页面。
- `/api/readings` 同时报告自动报警条件、当前模式、LED 实际逻辑输出和传感器状态，避免把自动条件误显示为手动灯状态。
- 手动操作只控制 D23，不改变温湿度读数。传感器读取失败时，自动模式沿用既有的最后有效 LED 状态；手动模式仍可操作 LED。
- 项目教程说明模式优先关系、网页操作和手动模式下自动报警暂停；项目仍是低压 LED 学习演示。

## 验收范围

- 在代码/API 层检查模式切换、手动开关、无效请求拒绝和切回自动时的阈值重算。
- 部署后用电脑或手机打开项目网页，确认模式和 LED 状态同步；物理点亮状态若未目视观察，单独标记未验证。
- 同步设备程序与 HTML 内嵌完整代码，更新验证记录和公开分享包。
