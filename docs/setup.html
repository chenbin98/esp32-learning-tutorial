开始前准备什么

本手记用电脑上的 Python 工具传输文件，用 ESP32 上的 MicroPython 运行硬件程序。先完成这页，再进入案例 01。

项目本次使用 / 说明
开发板ESP32-D0WD-V3，4 MB Flash；D2 按 GPIO2 使用
连接支持数据传输的 USB 线；仅有供电不代表能上传
电脑macOS 已实测；下方提供 Windows / Linux 命令差异，但尚未实机验证
软件CPython 3.12.2、esptool 5.6.0、mpremote 1.29.0
固件ESP32_GENERIC-20260824-v1.29.0.bin
LED先用接在 GPIO2 上的板载 LED；外接时需要限流电阻和共地

把项目解压到自己的目录，并在该目录打开终端。后续命令均从项目根目录执行。终端命令块不含 # 注释行，可直接复制。

1. 安装电脑端工具

先安装 Python 3.12。macOS / Linux 可使用下面的标准 Python 方式创建环境：

python3 --version
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt

本项目也可使用已安装的 uv：

uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python -r requirements.txt
source .venv/bin/activate
Windows PowerShell 命令
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe scripts/device.py ports

之后把命令中的 python 替换为 .venv\Scripts\python.exe，即可不依赖激活脚本。此平台分支尚未实测。

requirements.txt 固定了本次工具版本。板上程序只使用 MicroPython 内置模块，不能在电脑上用普通 Python 直接运行 machine.Pin。

2. 找到开发板串口

python scripts/device.py ports

找到插入开发板后出现的 USB 串口。本次是 /dev/cu.usbserial-0001，你可能看到 /dev/cu.usbmodem…、Linux 的 /dev/ttyUSB0 或 Windows 的 COM3。把后续命令中的端口替换成实际值。

如果只有蓝牙或 debug-console，说明尚未找到板子的串口：先重新插拔、换数据线或接口，再运行上述命令。若端口存在但被占用，关闭其他串口监视器后重试。

3. 首次安装 MicroPython

已经能运行案例程序的开发板，可以跳过本节。先识别芯片：

python -m esptool --port /dev/cu.usbserial-0001 chip-id

从 官方板型下载页选择正确的固件。下面命令仅针对本手记的经典 ESP32 / ESP32_GENERIC，C3、S3 等型号按各自页面操作。

本次使用 ESP32_GENERIC v1.29.0 固件，下载后放到 firmware/。

擦除会清空板上原固件和文件。

先保存要保留的程序。如果需要保存整片 Flash，本板 4 MB 的读取命令如下；必须看到读取成功并确认文件大小，才能把它当作备份。本次学习过程中的完整备份失败，未得到可恢复的原始镜像。

python -m esptool --port /dev/cu.usbserial-0001 --baud 115200 read-flash 0 0x400000 original-flash.bin

确认板上内容可以替换后，再执行擦除和刷写：

python -m esptool --port /dev/cu.usbserial-0001 erase-flash
python -m esptool --port /dev/cu.usbserial-0001 --baud 115200 write-flash 0x1000 firmware/ESP32_GENERIC-20260824-v1.29.0.bin

看到 Hash of data verified 表示固件写入校验通过。本次高速连接出现错误，改用 115200 完成刷写。上述地址 0x1000 来自 本板官方说明。

4. 确认环境可用

python -m mpremote connect /dev/cu.usbserial-0001 exec "import sys; print(sys.implementation)"
python scripts/device.py deploy 01 --port /dev/cu.usbserial-0001 --dry-run

第一条会中断当前板上程序，输出应包含 micropython 与版本信息。第二条只检查本地案例文件并显示上传路径，不接触开发板。

现在进入案例 01，按接线和上传步骤操作。之后修改 Python 脚本，只需重新上传，无需反复擦除固件。

我遇到的问题

现象实际观察 / 处理
zsh: command not found: #交互式 zsh 没把粘贴的 # 行当注释。去掉注释行即可，不能据此判断 Python 安装失败。
failed to access 串口本次曾是设备路径不存在；先列出串口，再区分断开、改名和占用。
Invalid head of packet / Read more than expected本次发生在 Flash 备份读取；降低波特率也未使完整备份成功。最终固件写入校验成功，不代表原固件已备份。
ModuleNotFoundError: machine板上 main.py 被电脑 Python 执行了。应通过上传工具部署到 MicroPython。
端口存在，连接仍失败关闭其他串口工具；检查线材、供电，必要时按 EN 复位。首次刷固件无法进入下载模式时，按板型说明使用 BOOT/EN。
