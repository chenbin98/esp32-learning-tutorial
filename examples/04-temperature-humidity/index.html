CASE 04 / DHT11 与网页

在网页上查看温湿度

ESP32 定时读取 DHT11，把温度与相对湿度显示在同一局域网的网页上。

DHT11Wi-Fi / HTTPD2 / GPIO2MicroPython 1.29.0

目标与工作方式

本案例用 DHT11 读取温度和相对湿度，ESP32 连接 Wi-Fi 并提供一个网页。页面每秒请求一次 JSON 接口，ESP32 每 2.5 秒读取一次传感器并返回缓存值，因此网页刷新不会让 DHT11 被过快采样。

DHT11DATA → D2 / GPIO2
→
ESP32MicroPython + Wi-Fi
↔ 局域网
电脑 / 手机浏览器自动刷新
浏览器只读取最近一次成功采样的数据；断开网络时会显示连接提示。

本板的 D2 对应 GPIO2。案例 04 会替换板上正在运行的 main.py，但部署工具会先备份旧文件。网页和案例 02 一样，需要电脑/手机与 ESP32 在可互通的局域网中。

传感器接线

DHT11 模块标签ESP32 接点说明
VCC / +3V3按你当前的接法供电；先核对具体模块是否支持 3.3V。
GND / -GND传感器与 ESP32 必须共地。
SIG / DATA / OUTD2 / GPIO2单总线数字数据。
先看模块上的针脚标记

三针模块和裸四针传感器的针脚顺序不一定一样，不要只按“从左到右”猜。裸 DHT11 通常还需要 DATA 到 3.3V 的上拉电阻；很多三针模块已经集成上拉。若模块不支持 3.3V，请按模块资料选择供电，并确保 DATA 到 ESP32 GPIO 的高电平不超过 3.3V（ESP32 GPIO 容忍上限为 3.6V）；不能因为传感器 VCC 接 5V 就让 DATA 也被上拉到 5V。

GPIO2 在 ESP32 上也参与启动配置。本板当前 D2 已用于前面的 LED 案例；本案例将它作为 DHT11 数据脚。若启动、刷写或数据读取不稳定，可断电后把 SIG 移到普通 GPIO（例如 GPIO4），并将源码中的 SENSOR_PIN 同步改为 4。

完整程序

部署工具会将这个案例的 main.py 上传到开发板，并把本地私人配置文件上传为 wifi_config.py。代码使用 MicroPython 固件自带的 dht 模块，不需要 pip 安装传感器驱动。

"""案例 04：通过 Wi-Fi 网页实时显示 DHT11 温湿度。"""
import dht
import network
import socket
import time
import ujson
from machine import Pin
from wifi_config import WIFI_SSID, WIFI_PASSWORD

SENSOR_PIN = 2             # 本板 D2 对应 GPIO2
SAMPLE_INTERVAL_MS = 2500   # DHT11 采样间隔需大于 2 秒

sensor = dht.DHT11(Pin(SENSOR_PIN))
latest = {
    "ok": False,
    "temperature": None,
    "humidity": None,
    "updated_ms": None,
    "error": "等待首次采样",
}

PAGE = '''<!doctype html>

def connect_wifi():
    if not WIFI_SSID:
        raise ValueError('Fill in wifi_config.py first')
    wlan = network.WLAN(network.WLAN.IF_STA)
    wlan.active(True)
    wlan.config(reconnects=-1)
    if not wlan.isconnected():
        print('Connecting to Wi-Fi...')
        wlan.connect(WIFI_SSID, WIFI_PASSWORD)
    start = time.ticks_ms()
    while not wlan.isconnected():
        if time.ticks_diff(time.ticks_ms(), start) > 30000:
            status = wlan.status()
            wlan.disconnect()
            raise RuntimeError('Wi-Fi timeout; check 2.4 GHz SSID/password. Status: %s' % status)
        time.sleep_ms(200)
    print('Open in browser: http://%s/' % wlan.ifconfig()[0])
    return wlan


def respond(client, status, body, content_type='text/html; charset=utf-8'):
    body = body.encode('utf-8')
    header = ('HTTP/1.1 %s\r\nContent-Type: %s\r\nContent-Length: %d\r\n'
              'Connection: close\r\nCache-Control: no-store\r\n\r\n'
              % (status, content_type, len(body)))
    client.write(header.encode('utf-8'))
    client.write(body)


def sensor_json():
    result = dict(latest)
    updated_ms = result.pop('updated_ms')
    result['age_ms'] = (time.ticks_diff(time.ticks_ms(), updated_ms)
                        if updated_ms is not None else None)
    return ujson.dumps(result)


def handle(client):
    client.settimeout(3)
    request = b''
    while b'\r\n\r\n' not in request:
        chunk = client.recv(256)
        if not chunk:
            return
        request += chunk
        if len(request) > 2048:
            respond(client, '431 Request Header Fields Too Large', 'Request too large')
            return
    parts = request.split(b'\r\n', 1)[0].split()
    if len(parts) != 3:
        respond(client, '400 Bad Request', 'Bad request')
    elif parts[0] == b'GET' and parts[1] == b'/':
        respond(client, '200 OK', PAGE)
    elif parts[0] == b'GET' and parts[1] == b'/api/readings':
        respond(client, '200 OK', sensor_json(), 'application/json; charset=utf-8')
    else:
        respond(client, '404 Not Found', 'Not found')


def sample_sensor():
    global latest
    try:
        sensor.measure()
        latest = {
            'ok': True,
            'temperature': sensor.temperature(),
            'humidity': sensor.humidity(),
            'updated_ms': time.ticks_ms(),
            'error': '',
        }
        print('Temperature: %s C, humidity: %s %%RH'
              % (latest['temperature'], latest['humidity']))
    except OSError as error:
        latest['ok'] = False
        latest['error'] = 'DHT11 读取失败，请检查接线和供电'
        print('DHT11 read error:', error)


def main():
    wlan = connect_wifi()
    sample_sensor()
    last_sample_ms = time.ticks_ms()

    server = socket.socket()
    server.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
    server.bind(('0.0.0.0', 80))
    server.listen(2)
    server.settimeout(1)
    try:
        while True:
            now = time.ticks_ms()
            if time.ticks_diff(now, last_sample_ms) >= SAMPLE_INTERVAL_MS:
                sample_sensor()
                last_sample_ms = time.ticks_ms()
            if not wlan.isconnected():
                wlan = connect_wifi()
            try:
                client, _ = server.accept()
            except OSError:
                continue
            try:
                handle(client)
            except OSError as error:
                print('Client error:', error)
            finally:
                client.close()
    finally:
        server.close()


if __name__ == '__main__':
    main()

关键流程：dht.DHT11(Pin(2)) 创建传感器对象，measure() 采样后再读温度和湿度。采样错误时串口会给出错误提示，网页保留上一次有效读数并显示错误状态。

上传并打开网页

  1. 确认项目中的 config/wifi_config.py 已填写可用的 2.4 GHz Wi-Fi 名称和密码；此文件只保存在本机，不要公开。
  2. 从项目根目录查看串口，确认开发板当前端口：
python scripts/device.py ports

将下面命令中的端口换成实际结果，然后上传案例 04：

python scripts/device.py deploy 04 --port /dev/cu.usbserial-0001 --repl

串口出现 Open in browser: http://设备IP/ 后，在同一局域网的电脑或手机浏览器中打开该地址。页面每秒更新一次显示状态，实际 DHT11 新采样约每 2.5 秒一次。按 Ctrl-] 退出串口终端，程序仍在开发板运行。

若刚从案例 02 切换过来，网页地址通常会由 DHCP 重新分配，应以串口本次打印出的 IP 为准。切回 LED 网页控制时重新部署案例 02。

验收与排错

现象检查方式
上传提示找不到 serial激活项目环境，并按 README 安装 requirements.txt 中的依赖；随后确认正在使用项目的 .venv/bin/python。
提示缺少 wifi_config.py把示例配置复制到 config/wifi_config.py 并填写自己的 Wi-Fi 配置。
串口反复显示 DHT11 读取失败逐条核对 VCC、GND、SIG 标签和共地；确认模块支持 3.3V、DATA 上拉是否已集成；按至少 2 秒的间隔采样。可断电后把信号线移到 GPIO4 并修改 SENSOR_PIN。
温湿度显示 --查看串口最早的采样错误；检查模块供电规格和 DATA 线，裸传感器需要正确上拉。
页面无法打开确认手机/电脑和 ESP32 在同一可互通的 Wi-Fi 局域网，使用串口打印的完整 IP。
