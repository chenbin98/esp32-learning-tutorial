Bluetooth LEMicroPython 1.29.0手机 BLE 工具待手机端实测

这一课要做什么

让手机发现 ESP32 的 BLE 设备，连接后向一个 GATT 特征值写入 on 或 off，控制 D2 / GPIO2 上的 LED。开发板不需要加入 Wi-Fi；手机通过蓝牙直接连接。

手机上的 nRF ConnectBLE Central / GATT Client
↔ BLE
ESP32-LED-03BLE Peripheral / GATT Server
→
D2 / GPIO2LED on / off
手机写入命令，ESP32 收到 GATT 写事件，再改变 GPIO 电平。

前置步骤：先完成案例 01，确认 LED 和 D2 / GPIO2 工作正常。案例 03 部署后会取代板上正在运行的 main.py；重新部署案例 02 即可回到 Wi-Fi 网页控制。

手机和电脑要准备什么

  • ESP32 已安装 MicroPython 1.29.0，并通过 USB 串口连到电脑。
  • iPhone 或 Android 手机，开启蓝牙。
  • 安装 nRF Connect for Mobile。它可扫描 BLE 设备、查看 GATT 服务与特征值，并写入特征值。
  • LED 接在 D2 / GPIO2；如果是外接 LED，沿用案例 01 的限流电阻接法。

案例使用 MicroPython 内置 bluetooth 模块，不需 pip 安装蓝牙包。它实现 BLE，不实现经典蓝牙 SPP 串口。这个案例选 BLE 是为了沿用当前 MicroPython 固件并直接用手机跨平台 GATT 工具连接。

先认清服务和特征值

项目本案例的值作用
广播设备名ESP32-LED-03在手机扫描结果中识别这块板。
GATT 服务FFF0将本学习案例的 LED 控制功能分组。
GATT 特征值FFF1可读、可写；手机从这里写开关命令。
点亮命令文本 onGPIO2 输出高电平，特征值读回 on。
熄灭命令文本 offGPIO2 输出低电平，特征值读回 off。

UUID 的完整形式如下。手机 App 中可能只显示短格式 FFF0、FFF1，也可能显示完整 UUID。

SERVICE     0000fff0-0000-1000-8000-00805f9b34fb
LED STATE   0000fff1-0000-1000-8000-00805f9b34fb

ESP32 是 GATT Server，维护 LED 当前特征值；手机是 GATT Client，读取或写入这个值。这是 BLE 应用层交互，并非操作系统里的传统“配对后虚拟串口”。

阅读并部署程序

源码：examples/03-bluetooth-led/main.py。电脑上的案例目录可以保留不同文件名，上传工具会把它装到板上的 main.py。

"""案例 03：手机通过 BLE GATT 写入指令控制 D2 / GPIO2 LED。"""
import bluetooth
import time
from machine import Pin

LED_PIN = 2
DEVICE_NAME = "ESP32-LED-03"
SERVICE_UUID = bluetooth.UUID(0xFFF0)
LED_CHARACTERISTIC_UUID = bluetooth.UUID(0xFFF1)
IRQ_CENTRAL_CONNECT = 1
IRQ_CENTRAL_DISCONNECT = 2
IRQ_GATTS_WRITE = 3
ADV_INTERVAL_US = 100_000

led = Pin(LED_PIN, Pin.OUT, value=0)
ble = bluetooth.BLE()
ble.active(True)
ble.config(gap_name=DEVICE_NAME)

service = (
    SERVICE_UUID,
    ((LED_CHARACTERISTIC_UUID, bluetooth.FLAG_READ | bluetooth.FLAG_WRITE),),
)
(led_state_handle,) = ble.gatts_register_services((service,))[0]
ble.gatts_write(led_state_handle, b"off")

name_bytes = DEVICE_NAME.encode()
advertisement = bytearray((2, 0x01, 0x06))
advertisement.extend((len(name_bytes) + 1, 0x09))
advertisement.extend(name_bytes)
connected = False
last_reported_connection = False


def start_advertising():
    ble.gap_advertise(ADV_INTERVAL_US, adv_data=advertisement)


def on_ble_event(event, data):
    global connected

    if event == IRQ_CENTRAL_CONNECT:
        connected = True
    elif event == IRQ_CENTRAL_DISCONNECT:
        connected = False
        start_advertising()
    elif event == IRQ_GATTS_WRITE:
        _, value_handle = data
        if value_handle != led_state_handle:
            return

        value = bytes(ble.gatts_read(led_state_handle))
        command = value.strip().lower()
        if command in (b"on", b"1") or value == b"\x01":
            led.on()
            ble.gatts_write(led_state_handle, b"on")
        elif command in (b"off", b"0") or value == b"\x00":
            led.off()
            ble.gatts_write(led_state_handle, b"off")
        else:
            state = b"on" if led.value() else b"off"
            ble.gatts_write(led_state_handle, state)


ble.irq(on_ble_event)
start_advertising()
print("BLE ready; scan for %s" % DEVICE_NAME)
print("Service UUID: 0000fff0-0000-1000-8000-00805f9b34fb")
print("LED characteristic UUID: 0000fff1-0000-1000-8000-00805f9b34fb")
print("Write on / off; read the characteristic to check the LED state.")

try:
    while True:
        if connected != last_reported_connection:
            print("Phone connected" if connected else "Phone disconnected; advertising again")
            last_reported_connection = connected
        time.sleep_ms(100)
finally:
    ble.gap_advertise(None)
    ble.active(False)
    led.off()

程序启动后以 ESP32-LED-03 名称广播。gatts_register_services 注册服务和特征值；BLE 收到手机写入时触发 IRQ_GATTS_WRITE，程序验证命令并改变 GPIO2。手机断开后，ESP32 会重新广播，等待下一次连接。

FFF0 和 FFF1 是学习案例自定义 UUID。特征值未配置配对或认证，附近能连接设备的手机都可以控制 LED；只在可信的学习环境中使用。

上传到 ESP32

在项目根目录执行。先确认当前 USB 串口名称，再部署案例 03：

source .venv/bin/activate
python scripts/device.py ports
python scripts/device.py deploy 03 --port /dev/cu.usbserial-0001 --repl

把示例端口替换为自己的端口。工具会备份板上的启动文件，上传并核对 SHA-256，然后重启进入 REPL。串口应显示类似：

BLE ready; scan for ESP32-LED-03
Service UUID: 0000fff0-0000-1000-8000-00805f9b34fb
LED characteristic UUID: 0000fff1-0000-1000-8000-00805f9b34fb
Write on / off; read the characteristic to check the LED state.

REPL 中按 Ctrl-] 退出。BLE 程序继续在开发板运行；若串口关掉，手机蓝牙连接仍可用。

用手机连接和控制

  1. 打开手机蓝牙和 nRF Connect，进入扫描页并开始扫描。
  2. 在扫描结果里找到 ESP32-LED-03，点击 Connect。手机若提示系统蓝牙权限，选择允许。
  3. 等待服务发现，找到服务 FFF0，再展开特征值 FFF1。
  4. 点击该特征值的写入按钮（常见图标为向上箭头）。在写入窗口选择 Text / UTF-8 模式，输入 on 并发送；观察 LED 点亮。
  5. 用同一个特征值发送 off，观察 LED 熄灭。
  6. 点击读取按钮，再读一次特征值；应分别看到 on 或 off。
如果 App 默认显示 Hex

将写入格式切换到 Text / UTF-8，再输入字母 on 或 off。如果坚持使用 Hex，on 对应 6F 6E，off 对应 6F 66 66；不要把 ASCII 文本误当作单字节 01 / 00。

写入后如果 UI 没自动刷新，手动按 Read 查看状态。这个案例没有启用通知，因此不会自动把 GPIO 状态推送到手机。

验收和排错

现象检查方式
搜索不到设备确认串口显示 BLE ready；手机蓝牙已开启；手机离板近一些；确认没有仍连接的其他手机；停止扫描再重新开始。
设备可连接但找不到服务等待服务发现完成；断开并重连。如手机缓存了旧 GATT 表，关闭并重新打开 nRF Connect 后再试。
能写入但 LED 不变确认选择 Text / UTF-8，写入严格为小写 on 或 off；确认连接的板子是本案例运行的设备；回到案例 01 检查 LED 接线和有效电平。
REPL 出现 NameError: bluetooth先在串口确认板上是 ESP32_GENERIC 的 MicroPython 固件；ESP32-C3/S3 需要对应固件并非所有版本都支持 BLE 特性相同。
断开后没有重新出现观察串口是否报告 Phone disconnected; advertising again；关闭手机连接，再重新扫描。

部署案例 01 或 02 会替换板上的 BLE 程序。需要回来时重新部署案例 03。
