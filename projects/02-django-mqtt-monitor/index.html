PRACTICAL PROJECT 02 / MQTT + DJANGO

温湿度监测与历史曲线

把案例 04 的网页温湿度采集、案例 05 的 OLED 显示和项目 01 的双阈值/手动 LED 控制，连到一台局域网电脑上的 Django 历史后台。

DHT11 · GPIO2SSD1315 OLED · 128×64 · I²CLED · D4 / GPIO4MQTTDjango + SQLite

目标与系统结构

ESP32 每约 2.5 秒采集一次温湿度，同时更新 OLED，并按本地阈值控制 D4 LED。设备通过 MQTT 向电脑发布采样值和状态；电脑端 MQTT Broker 转发消息，Django 后台保存历史并提供网页、当前值、曲线和控制接口。

OLED 在 ESP32 本地显示；自动阈值由 ESP32 判断，网页手动命令经 MQTT 返回设备。数据库时间为电脑接收时间。

建议先完成 案例 04、案例 05 和 项目 01。本项目包含独立设备程序和 Django 服务。

接线与控制规则

模块ESP32 接口说明
DHT11DATA → D2 / GPIO2VCC/GND 按模块规格，与 ESP32 共地。
SSD1315 OLED · 128×64SCL → D18 / GPIO18；SDA → D19 / GPIO19默认 I²C 地址 0x3C；屏幕采用左右分栏，大号数字显示温湿度。
LEDD4 / GPIO4 串联 330 Ω 电阻正极经电阻接 GPIO4，负极接 GND；高电平点亮。
无源蜂鸣器D15 / GPIO15信号端接 GPIO15，GND 共地；阈值报警时以 2 kHz PWM 间歇鸣叫。
静音按钮D21 / GPIO21按钮一端接 GPIO21，另一端接 3.3 V；程序启用内部下拉，按下为高电平。

沿用项目 01 阈值：温度 >25°C 且湿度>60% RH 才在自动模式点亮；任一条件不满足就关闭。手动模式暂停自动判断，网页可点亮或关闭 LED。温湿度同时超过阈值时 D15 蜂鸣器以 2 kHz、约每 250 ms 开/关的节奏报警；按下 D21 按钮可让本次报警静音。温湿度恢复到阈值范围后静音状态复位，下次报警会再次鸣叫。设备重启后默认自动模式。

接线确认

请以开发板丝印和原理图确认 D4 对应 GPIO4。LED 必须串联限流电阻；OLED/DHT11 信号电压需兼容 ESP32 3.3V。网页接口无账号认证，只用于可信局域网。

电脑端准备

  1. 创建项目虚拟环境并安装 Django、Paho 与 Python Broker：
    python -m venv projects/02-django-mqtt-monitor/.venv
projects/02-django-mqtt-monitor/.venv/Scripts/python.exe -m pip install -r projects/02-django-mqtt-monitor/requirements.txt
    macOS/Linux 将 Scripts/python.exe 换成 bin/python。
  2. 在项目根目录的终端启动 Broker：projects/02-django-mqtt-monitor/.venv/Scripts/amqtt.exe（已激活项目虚拟环境时运行 amqtt）。它监听 0.0.0.0:1883。本例无 MQTT 认证，仅用于可信局域网；不要暴露到公网。
  3. 复制 config/project_02_config.example.py 为 config/project_02_config.py，将 MQTT_HOST 改为电脑的局域网 IPv4 地址。
  4. 确保 config/wifi_config.py 已填写 ESP32 可接入的 2.4 GHz Wi-Fi。
  5. 在一个终端进入 projects/02-django-mqtt-monitor，运行 .venv\Scripts\python.exe manage.py migrate，随后运行 .venv\Scripts\python.exe manage.py mqtt_worker。该终端保持运行。

另开终端进入同一项目目录，运行 .venv\Scripts\python.exe manage.py runserver 0.0.0.0:8000。电脑打开 http://127.0.0.1:8000/；局域网其他设备访问 http://电脑局域网IP:8000/。Django 开发服务器只用于可信局域网演示，不用于公网部署。

部署 ESP32

复制并填写上述 Wi-Fi 与项目配置后，设备部署工具会上传配置和 main.py：

python scripts/device.py ports
python scripts/device.py deploy project-02 --port COM3 --repl

将 COM3 换成实际串口。MicroPython 端使用内置的轻量 MQTT 3.1.1 QoS 0 客户端，无需额外库文件。依赖版本见项目 requirements.txt。Django 5.2 是长期支持版本，支持 Python 3.10–3.14；官方发布说明 · Paho MQTT 文档

网页查看与控制

  • 页面约每秒刷新当前值、设备在线状态、模式和 LED 实际状态；传感器约每 2.5 秒采样。
  • 历史曲线默认近 24 小时，可切换近 6 小时、3 天或 7 天。每个有效采样会保存在本地 SQLite。
  • “自动模式”恢复双阈值判断；“手动点亮/关闭”切到手动模式，命令经 MQTT 返回设备并等待状态回报。
  • 电脑后台断开时，ESP32 本地自动控制仍运行；网络恢复后重新上报。首版不缓存掉线期间的数据。

验收与边界

  • OLED 显示当前温湿度和 LED 状态。
  • Django 页面能显示当前读数并刷新历史曲线。
  • SQLite 保存连续采样记录，可按时间范围绘制温度和湿度曲线。
  • 双阈值自动控制、网页手动点亮/关闭、设备状态回报均符合预期。
  • 温湿度同时超阈值时 GPIO15 蜂鸣器有节奏鸣叫；按 GPIO21 按钮后静音，报警解除后下一次报警可再次鸣叫。
  • 电脑/MQTT 断开时，本地采样、OLED 和自动 LED 判断继续运行。

首版仅支持单设备、可信局域网和未认证 MQTT；多设备、账号权限、部署加固、掉线补传留到后续阶段。此代码尚未标记为实机验收完成，需按上述清单在实际设备确认。
