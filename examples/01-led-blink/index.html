CASE 01 / GPIO 与第一次上传

点亮第一盏 LED

从两行高低电平控制，开始建立“修改 → 上传 → 观察”的开发习惯。

ESP32 / WROOMMicroPython 1.29.0实做记录 + 复现步骤

这一课要做成什么

让 D2 上的 LED 亮 1 秒、灭 1 秒，持续循环。完成后，你会知道如何控制 GPIO、如何改变节奏，以及怎样把修改后的脚本上传到开发板。

0–1 s
亮1–2 s
灭2–3 s
亮3–4 s
灭4–5 s
亮5–6 s
灭
每 1 秒切换一次；一次完整的亮灭周期为 2 秒。

前置步骤：完成 环境准备，确认串口可见、板上已经安装 MicroPython。

接线与引脚

本开发板 D2 对应 GPIO2。若板载 LED 已连接到 GPIO2，可直接使用。其他板子的板载灯可能连接到不同引脚，或是 RGB LED，需先查引脚图。

D2 / GPIO2输出高低电平
→
330 Ω 电阻串联限流
→
LED 正极 → 负极负极接 GND
外接普通指示 LED 的逻辑接线示意；断电接线，GPIO 使用 3.3 V 逻辑。

此接法高电平点亮，代码设 LED_ON = 1。低电平点亮的板载 LED 应改为 LED_ON = 0。

阅读完整程序

文件：examples/01-led-blink/main.py（下载）。电脑端案例名称保留在目录中，上传到板上时统一叫 main.py。

"""案例 01：D2 / GPIO2 LED 亮 1 秒，灭 1 秒。"""
from machine import Pin
from time import sleep

LED_PIN = 2             # 本板 D2 对应 GPIO2；其他板请核对引脚图
LED_ON = 1              # 高电平点亮；低电平点亮的 LED 改为 0
INTERVAL_SECONDS = 1    # 每次亮 / 灭持续的时间，完整周期为它的两倍

led = Pin(LED_PIN, Pin.OUT, value=1 - LED_ON)

try:
    while True:
        led.value(LED_ON)
        sleep(INTERVAL_SECONDS)
        led.value(1 - LED_ON)
        sleep(INTERVAL_SECONDS)
finally:
    led.value(1 - LED_ON)
代码含义
Pin(..., Pin.OUT)把 GPIO 配置成数字输出，初始电平设为熄灭。
led.value(...)给引脚写入 0 或 1。实际灯的亮灭取决于接线和有效电平。
sleep(1)暂停约 1 秒；在这个入门案例中使用阻塞延时。
finally正常中断循环时尝试把灯关掉；断电和硬复位不依靠此语句执行。

上传并运行

在项目根目录激活环境，再确认串口名称：

source .venv/bin/activate
python scripts/device.py ports
python scripts/device.py deploy 01 --port /dev/cu.usbserial-0001

工具会检查文件、备份板上同名文件、上传临时文件并校验 SHA-256，成功后替换启动文件并重启。它不会擦除 MicroPython 固件。

理解底层操作：不用封装工具怎么上传？
python -m mpremote connect /dev/cu.usbserial-0001 fs cp examples/01-led-blink/main.py :main.py
python -m mpremote connect /dev/cu.usbserial-0001 reset

这组命令直接覆盖板上 main.py，不包含教程工具提供的备份和哈希校验。

如果之前运行的是 Wi-Fi 案例，此操作会切换到闪烁案例，网页服务随之停止。切回案例 02 时再次部署即可。

验收与修改

修改 INTERVAL_SECONDS 后，保存并重复同一条部署命令。不要直接在普通 Python 解释器里运行这个文件。

想中断程序，执行下面的终端命令，然后按 Ctrl-C；Ctrl-D 软重启，Ctrl-] 退出终端：

python scripts/device.py repl --port /dev/cu.usbserial-0001

不亮时从哪里查

现象检查顺序
有上传成功提示但灯不亮确认 D2 是否为 GPIO2 → 是否确有 LED 接在该引脚 → 正负极与电阻 → LED_ON 的有效电平。
灯一直亮或一直灭核对改动后的文件是否保存、是否上传了案例 01、是否重启。
上传报串口访问失败运行 ports；看不到设备则检查 USB 数据连接，看到设备则检查占用。
出现 traceback连接 REPL 查看异常行号，修正脚本后重新部署。
