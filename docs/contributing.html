每个案例保留同一种结构

一个案例解决一个可以观察的小问题。教程与源码放在同一目录，编号递增。旧案例保留，方便后来的人从头复现。

examples/
  01-led-blink/
    index.html
    main.py
    case.json
  02-wifi-led/
    index.html
    main.py
    case.json
    wifi_config.example.py
  03-your-next-case/
    ...

建议按“要做什么 → 前置条件与接线 → 核心原理 → 修改和上传 → 预期结果 → 我的过程 → 排错 → 练习”写。日期、平台和验证范围都要明确。

从模板开始下一篇

  1. 复制 templates/case/ 到 examples/05-your-next-case/。
  2. 修改 HTML 的标题、目标、接线、步骤与记录，替换 TODO。
  3. 实现 main.py，保持清晰的小程序；配置秘密放在 config/，公开目录中只提供 example 模板。
  4. 更新 case.json 中的文件清单，文件名映射明确指向板上根目录。
  5. 在首页增加案例卡片，并修改上一案例的“下一篇”导航。
  6. 先检查、再部署，保存实际结果。未验证的教程保留“草稿”标识。

查看案例模板。上传工具可识别新目录编号；教程检查脚本、首页入口与下一篇导航也应同步更新。

python scripts/device.py deploy 05 --port /dev/cu.usbserial-0001 --dry-run

如果案例增加其他源文件，除部署清单外，还应把它加入分享脚本的公开文件范围，并重新检查 ZIP 内容。当前分享脚本只收录标准案例文件。

怎样写一条可信的学习记录

内容推荐记录
目标这次希望哪个行为发生变化，例如亮 1 秒改为亮 0.1 秒。
环境板型、固件、工具版本、接线、日期。
过程关键命令、出现的错误及处理办法；凭据和私人信息脱敏。
证据上传回读、HTTP 返回、现场肉眼观察分别说明；不要相互替代。
未完成断网恢复、其他板型、跨系统等未实测的部分直接标明。

本项目根目录的 task_plan.md、findings.md、progress.md 用于维护项目和接续工作，学习者阅读 HTML 即可。分享包不收录这些本地工作记录。

检查并生成分享包

python -m unittest discover -s tests -v
python scripts/check_tutorial.py
python scripts/package_tutorial.py

生成 dist/esp32-learning-tutorial.zip。它采用明确的公开文件范围，只包含 HTML、样式、示例代码、依赖和工具。不会打包 config/wifi_config.py、.venv、backups、固件镜像或本地日志。

把 ZIP 发给其他学习者，他们解压后打开 esp32-learning/index.html，按环境准备重新建立自己的开发环境与 Wi-Fi 配置。不要直接压缩整个工作目录分享。
