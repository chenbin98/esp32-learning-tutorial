# 教程组织设计

日期：2026-10-27。用户要求将前两个实践整理为持续增长的案例教程，并在此基础上增加手机 BLE 控制 LED 的案例 03，以及 DHT11 网页温湿度监测案例 04。

## 选择

采用纯静态 HTML + 独立 MicroPython 案例。学习者不需要 Node、网站构建器或云服务就能阅读；每个案例保持可独立上传的 main.py。统一样式只服务教程，设备网页仍内嵌于案例 02 的程序。

每个案例各自是独立程序：学习者通过上传案例明确切换板上的行为，更容易理解每一步。

## 职责

- `index.html`：学习路径和案例目录。
- `docs/setup.html`：共用环境；`docs/contributing.html`：新增案例和分享流程。
- `examples/NN-name/index.html`：过程、使用说明、验证范围、练习和官方参考。
- `examples/NN-name/main.py`：设备端程序；`case.json`：电脑端部署清单。
- 案例 03 采用 MicroPython BLE peripheral/GATT server；手机用 nRF Connect 作 central/client，通过 FFF0/FFF1 的可写特征值发 on/off 指令。低层 BLE API 与固件 v1.29.0 配套。
- 案例 04 采用 MicroPython 内置 DHT11 驱动，GPIO2 读取温湿度；ESP32 复用 Wi-Fi 配置并提供 `/api/readings` JSON 接口，浏览器每秒拉取缓存，设备约每 2.5 秒测量一次。
- `config/`：个人配置；示例值留在公开的 `.example.py`。
- `scripts/device.py`：按清单校验路径、检查本地文件、备份板上同名文件、临时上传、比对 SHA-256、替换并重启。必须明确指定端口；dry-run 不操作设备。
- `scripts/package_tutorial.py`：公开文件范围打包，而非任意递归目录。

## 本次行为影响

案例 01 从历史快照中整理为 1 秒亮、1 秒灭；新增常量以支持引脚和有效电平调整。
案例 02 与前一版保持一致，仍是单客户端 HTTP 服务器；连接失败约 30 秒后报错，不承诺长期断网自愈。案例 03 不使用 Wi-Fi，在手机断连后重新广播。案例 04 新增独立温湿度网页程序，不改变案例 02 LED 示例。
配置路径只在电脑上变化；板上仍是 main.py + wifi_config.py。重组本身不修改设备。

## 延续规则

新增案例从模板复制。首页入口、上一案例导航、部署清单和分享范围一起检查。
教程中完整代码与源码必须一致；修改源码后同步 HTML，check_tutorial.py 会核对每个案例的完整代码块。
历史验证需注明时间，软件状态与现场观察分开记录。计划文件记录维护进度，不作为公开教程正文。

## 验证策略

本地检查路径、HTML 引用、内嵌完整代码一致性、脚本语法和分享边界；上传工具的既有测试覆盖校验失败不替换启动文件。
浏览器检查首页与案例页面桌面/手机宽度、导航和复制操作。当前已运行的硬件案例不因文档重组而重新部署。
